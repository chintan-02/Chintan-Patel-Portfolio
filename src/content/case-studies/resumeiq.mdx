## Problem

Resume tools often compress many different issues into one unexplained score.

A candidate may have a parsing problem, missing keywords, weak skill visibility, incomplete structure, generic writing, or poor job-description alignment. One percentage does not tell the user which problem exists or what to improve.

Hiring-related AI also creates privacy and responsible-AI risks. Resume content can contain personal information, and an analysis tool should not quietly become an automated hiring decision system.

## Solution

ResumeIQ converts resumes and job descriptions into separate, reviewable signals.

The current application supports PDF, DOCX, and TXT parsing, local text normalization, baseline TF-IDF role classification, keyword and semantic job-description matching, normalized skill extraction, skill-gap analysis, ATS-style structure and content signals, sentence-quality review, humanized rewrite guidance, batch comparison, reviewer notes, and shortlist foundations.

The primary Streamlit application can operate locally even when the optional FastAPI service is unavailable. When enabled, FastAPI adds typed analysis, readiness, persistence, local retrieval, and safe prompt-preview foundations without being presented as the only runtime source of truth.

## Why multiple signals instead of one score?

A single score hides the reason behind the result.

ResumeIQ keeps these components separate:

- parsing quality
- baseline role prediction
- keyword overlap
- semantic similarity
- matched and missing skills
- structure and completeness
- sentence quality
- human reviewer interpretation

This is both an explainability decision and a product decision. The user can see which signal needs attention instead of treating one number as objective hiring truth.

A credible final evaluation should include stratified cross-validation, per-class precision and recall, macro and weighted F1, confusion-matrix analysis, calibration, duplicate checks, semantic-matching benchmarks, error analysis, and responsible-AI review.

## Privacy and responsible AI

Current boundaries include:

- human review remains required
- protected attributes are not intentionally used for scoring
- full resume and job-description text should not be persisted unnecessarily
- selected displays can mask common personal information
- fairness visualizations are explicitly synthetic or demonstration-only
- external GenAI is disabled by default
- ATS-style outputs are educational estimates, not official ATS scores
- no autonomous hiring action is performed

The local recruiter-copilot foundation is not presented as a production RAG system, and the prompt-preview endpoint builds and validates prompts without sending resume data to an external provider.

## Engineering foundations

Beyond the visible Streamlit workflow, the repository includes:

- FastAPI health, readiness, and version endpoints
- typed Pydantic contracts
- SQLite and SQLAlchemy persistence foundations
- local model-registry and MLflow foundations
- structured application logging
- Docker Compose development setup
- pytest coverage
- GitHub Actions continuous integration
- optional API fallback behaviour

These are engineering foundations rather than claims of a fully distributed production platform.

## Current limitations and roadmap

Current limitations include incomplete independent model validation, educational ATS-style scoring, semantic matching that needs benchmarking, Streamlit as the primary interface, optional rather than authoritative FastAPI integration, local SQLite persistence, demonstration authentication, partial PII masking, synthetic fairness views, disabled external GenAI, and no production monitoring.

The next high-value work is:

- complete leakage, duplicate, and split-quality analysis
- compare baseline models under a stronger evaluation protocol
- add calibration and per-class reporting
- benchmark semantic job matching
- strengthen privacy and document-lifecycle controls
- evaluate a React or Next.js migration only when it improves the product architecture
- add production observability and deployment hardening

## What this project demonstrates

ResumeIQ demonstrates multi-format parsing, NLP preprocessing, TF-IDF classification, semantic and keyword matching, skill normalization, explainable multi-signal product design, privacy-aware workflow decisions, FastAPI and persistence foundations, Docker and CI, Azure deployment, and honest evaluation positioning.
