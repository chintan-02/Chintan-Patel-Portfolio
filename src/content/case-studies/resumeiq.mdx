## Why I built ResumeIQ

Keyword overlap can show that a resume mentions a tool. It gives a candidate little guidance on whether their resume shows using, building with, or owning work on that tool. A generated rewrite can then turn a contribution into a leadership claim. I built ResumeIQ so candidates can see what their documents actually support before deciding what to rewrite or leave out.

## How it works

1. Add a job posting and use the synthetic sample or upload a PDF, DOCX, or TXT resume. The API extracts text in memory and masks contact details.
2. Inspect the fit map. Each extracted requirement is marked backed, partly backed, or missing evidence. A supporting citation points to a verified span of the document.
3. Review the tailor plan and draft a bullet from the cited evidence. Optional model generation is evaluated by deterministic checks covering scope, verbs, tools, numbers, and unsupported wording. An edit clears the current check and requires a fresh check before approval.

## Architecture

The Next.js client on Vercel calls its own backend routes. Those routes forward requests to FastAPI on Cloud Run. Requirement extraction and matching use rules and run without a model. Optional Claude drafting receives the masked requirement and cited lines. The API checks the proposed bullet and can retry once or fall back to a rule-based draft.

## Engineering milestones

| Milestone | What shipped |
| --- | --- |
| Evidence baseline | Exact citation offsets, a labeling guide, and reproducible keyword and embedding baselines. |
| Public deployment | Next.js on Vercel, FastAPI on Cloud Run, and a synthetic walkthrough. |
| Tailoring workflow | Multi-format uploads, a fit map and tailor plan, claim checking, rechecks on edits, and report export. |
| Evaluation and reliability | Per-skill evidence strength, versioned holdouts, live-model audits, rate limits, and operational logging. |

## What the evaluation showed

| Measure | Result |
| --- | --- |
| Matcher v3 on 34 synthetic held-out cases | **0.77 macro-F1**, up from 0.69 for v2 on the same set. Evidence recall@3 was 0.95 for both. |
| Claim checker v3 on the synthetic holdout | **20/20** overstated drafts blocked and **3/20** honest drafts wrongly blocked. |
| Live model audit | **3/15** model-generated final bullets were flagged as borderline by an AI audit. |
| Automated checks | **148 API tests** and **20 web tests** passed. Four committed evaluation reports reproduced exactly. |

These are small, synthetic holdouts with AI-drafted labels. The matcher can still attach a strong verb to unrelated work, and the live audit shows why candidates should review any approved wording. See the [matcher report](https://github.com/chintan-02/resumeiq/blob/main/evals/reports/eval_v2/REPORT.md), [checker report](https://github.com/chintan-02/resumeiq/blob/main/evals/reports/claimcheck_v3/REPORT.md), and [live drafting audit](https://github.com/chintan-02/resumeiq/blob/main/evals/reports/drafting_v2/NOTES.md).
